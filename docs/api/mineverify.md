# MineVerify API

## Base URL

```text
http://localhost:3000/api
```

## Overview

These endpoints are called by the MineVerify Minecraft server plugin, not by the browser.

Every request must include the shared bearer token configured with `MINEVERIFY_TOKEN`.

```http
Authorization: Bearer <MINEVERIFY_TOKEN>
```

## Endpoints

### GET `/mineverify/pending-requests`

Returns Minecraft account link requests waiting for a code generated by MineVerify.
Temporary request state is stored in PostgreSQL so every application instance sees the same data.

**Body:** none.

**Response:**

```json
{
  "requests": [
    {
      "requestId": "018f4f58-6fb7-7f65-bd2a-8a6f7c83f8e1"
    }
  ]
}
```

Returns an empty list when no pending request exists.

### POST `/mineverify/code-created`

Stores the generated MineVerify code and its expiration date in the temporary request table.
Repeating the callback with the same code succeeds without changing the original request. A
different code for the same request is rejected.

**Request body:**

```json
{
  "requestId": "018f4f58-6fb7-7f65-bd2a-8a6f7c83f8e1",
  "code": "K7M9-P2Q4",
  "expiresAt": "2026-06-04T16:05:00Z"
}
```

**Response:**

```json
{
  "ok": true
}
```

### POST `/mineverify/validated`

Receives the verified Minecraft identity from MineVerify and persists the final account link.

**Request body:**

```json
{
  "requestId": "018f4f58-6fb7-7f65-bd2a-8a6f7c83f8e1",
  "code": "K7M9-P2Q4",
  "minecraftUuid": "6f8f5771-8ec8-4b8d-bc40-8cbe2f84f5a3",
  "minecraftName": "PlayerName",
  "validatedAt": "2026-06-04T16:02:20Z"
}
```

**Internal logic:**

- Finds the temporary request by `requestId`.
- Verifies that the code matches the stored MineVerify code.
- Rejects expired requests and accepts identical validation retries.
- Refuses the link if the Minecraft UUID is already linked to another PMC Plan account.
- Upserts the durable `MinecraftProfile` identified by the verified UUID.
- Links that profile to the `User` through the unique `linkedUserId` relation.
- Stores the current player name and link timestamp on `MinecraftProfile`.
- Marks the temporary request as validated in the same serializable transaction.

**Response:**

```json
{
  "ok": true
}
```

### POST `/mineverify/expired`

Marks a MineVerify request as expired when the plugin reports an unused code expiration or a graceful server shutdown.

**Request body:**

```json
{
  "requestId": "018f4f58-6fb7-7f65-bd2a-8a6f7c83f8e1",
  "code": "K7M9-P2Q4"
}
```

**Internal logic:**

- Finds the temporary request by `requestId`.
- Verifies that the code matches when a code is already stored.
- Stores the expiration timestamp using the current app server time.
- Accepts identical expiration retries and rejects already validated requests.

**Response:**

```json
{
  "ok": true
}
```

## Temporary Request Lifecycle

`MinecraftLinkRequest` contains only the state needed to coordinate the browser, MineVerify,
and potentially several application instances:

- A pending browser request remains available to the plugin for 10 minutes.
- A plugin-generated code remains valid until its supplied `expiresAt` timestamp.
- Validated and expired requests are retained for 24 hours to support safe callback retries.
- Old terminal requests are removed opportunistically during normal MineVerify API activity.
- Unlinking clears `linkedUserId` and `linkedAt`, then removes the user's remaining
  temporary requests.
- The `MinecraftProfile` itself is retained because it may still be displayed as a
  public owner of map entries.

The durable account identity is stored in `MinecraftProfile`. The optional unique
relation to `User` represents the active PMC Plan account link.
